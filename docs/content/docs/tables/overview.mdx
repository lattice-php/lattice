A table is a listing backed by a **data source**. You declare columns in PHP; Lattice renders the
React table and handles sorting, filtering, and pagination, fetching rows from the table's
[endpoint](/advanced/security/). Nothing about a table is tied to a database — a table is a
`TableDefinition` plus a [source](/tables/data-sources/) that turns a request into rows. An
[Eloquent source](/tables/eloquent-tables/) ships out of the box, and an in-memory array, an HTTP API,
or a search index works just as well.

## How a table loads data

Every sort, filter, and page change is a fresh `GET` to the table's endpoint. The request becomes a
`TableQuery` that the data source turns into rows — so the React table never holds the full dataset, it
asks for the page it needs:

<Mermaid
  title="Fetching a page of rows through the data source"
  code={`sequenceDiagram
    autonumber
    actor U as User
    participant B as Browser (React)
    participant L as Lattice backend (table endpoint)
    participant D as Data source
    U->>B: Open the page
    B->>L: GET page
    L-->>B: Page payload — signed table (columns + ref)
    B->>L: GET table endpoint — sort, filter, page
    L->>L: build TableQuery from the request
    L->>D: source.query(TableQuery)
    D-->>L: TableResult — rows + pagination
    L-->>B: rows + pagination metadata
    B->>U: Render the table
    U->>B: Sort / filter / paginate
    B->>L: GET table endpoint — updated query
    Note over B,L: same round-trip, new TableQuery`}
/>

## Defining a table

Extend `TableDefinition` and implement its two abstract methods — `columns()` and `source()`. The
`#[AsTable]` attribute gives the table a stable id so it can be discovered and addressed by its own
endpoint.

```php
use Lattice\Table\Attributes\AsTable;
use Lattice\Table\CallbackTableSource;
use Lattice\Table\Columns\NumberColumn;
use Lattice\Table\Columns\TextColumn;
use Lattice\Table\Contracts\TableSource;
use Lattice\Table\TableDefinition;
use Lattice\Table\TableQuery;
use Lattice\Table\TableResult;

#[AsTable('app.products')]
class ProductsTable extends TableDefinition
{
    public function columns(): array
    {
        return [
            TextColumn::make('name')->sortable()->filterable(),
            NumberColumn::make('price')->sortable(),
        ];
    }

    public function source(): TableSource
    {
        return new CallbackTableSource(
            fn (TableQuery $query) => TableResult::fromItems($this->rows()),
        );
    }
}
```

<Info>
  Backing a table with an Eloquent model is common enough that
  [`EloquentTableDefinition`](/tables/eloquent-tables/) implements `source()` for you — you write a
  `builder()` instead. It is a convenience over the same `TableSource` contract, not a separate kind
  of table.
</Info>

Everything except the source is declared the same way whatever backs the table. `TableDefinition`
exposes these hooks beyond `columns()` and `source()`:

| Method               | Purpose                                                                                       |
| -------------------- | --------------------------------------------------------------------------------------------- |
| `columns()`          | The columns to render — see [Columns](/tables/columns/overview/).                             |
| `source()`           | The [data source](/tables/data-sources/) that turns a query into rows.                        |
| `filters()`          | Table-level [dedicated filters](/tables/filtering/#dedicated-filters).                        |
| `perPage()`          | Rows per page (default `25`).                                                                 |
| `pagination()`       | The [pagination mode](/tables/sorting-and-pagination/#pagination).                            |
| `striped()`          | Alternate row shading.                                                                        |
| `resizableColumns()` | Let users drag column borders to resize. Widths persist per table in the browser.             |
| `resizeIndicator()`  | Show a drag indicator on column borders when resizing is enabled.                             |
| `pinnableColumns()`  | Let users pin columns from the columns menu — see [Pinned](/tables/columns/overview/#pinned). |
| `emptyLabel()`       | Text shown when the table has no rows (default "No results").                                 |
| `actionsLabel()`     | Accessible label for the row-actions column (default "Actions").                              |
| `actions($row)`      | Per-row [actions](/tables/actions/).                                                          |
| `rowDetail($row)`    | Expandable [row detail](/tables/row-detail/) fragment.                                        |
| `rowUrl($row)`       | Makes the whole row clickable — see [Row links](/tables/row-detail/#row-links).               |
| `bulkActions()`      | [Bulk actions](/tables/actions/#bulk-actions) for selected rows.                              |

Each hook is a method you override. For example, to enable resizable columns with a drag indicator:

```php
public function resizableColumns(): bool
{
    return true;
}

public function resizeIndicator(): bool
{
    return true;
}
```

Resized widths are remembered per table in the browser, with a control to reset them to the defaults.

## Rendering a table

Render a table on a page with `Table::use()`, passing the definition class:

```php
use Lattice\Table\Components\Table;

Table::use(ProductsTable::class);
```

`Table::lazy()` renders the same table but defers the first data load until the component mounts —
useful inside a tab or a section that isn't visible on page load.

## Client-side shell

The presentational shell of the table — the bordered frame, toolbar, header and body grids, pinned
tracks, empty state, and footer — is exported from `@lattice-php/table` as a set of `DataTable*`
primitives. They take plain props instead of wire nodes and carry no data loading, sorting, or
selection state; the Lattice table composes them, so a static table built from the same primitives
looks identical to a live one.

```tsx
import {
  DataTable,
  DataTableBody,
  DataTableCell,
  DataTableEmpty,
  DataTableFooter,
  DataTableGrid,
  DataTableHeader,
  DataTableHeaderCell,
  DataTableHeaderRow,
  DataTablePagination,
  DataTableRow,
  DataTableSearch,
  DataTableSortButton,
  DataTableToolbar,
} from "@lattice-php/table";
import { buildColumnGridTemplate } from "@lattice-php/ui";

const columns = [
  { key: "name", label: "Name", width: "lg" },
  { key: "price", label: "Price", width: "sm", align: "end" },
] as const;

<DataTable>
  <DataTableToolbar
    start={
      <DataTableSearch
        value={term}
        placeholder="Search"
        clearLabel="Clear search"
        onValueChange={setTerm}
        onClear={() => setTerm("")}
      />
    }
  />
  <DataTableGrid columns={buildColumnGridTemplate({ columns })}>
    <DataTableHeader>
      <DataTableHeaderRow>
        <DataTableHeaderCell sortDirection="asc" bottomBordered>
          <DataTableSortButton direction="asc">Name</DataTableSortButton>
        </DataTableHeaderCell>
        <DataTableHeaderCell align="end" bottomBordered>
          Price
        </DataTableHeaderCell>
      </DataTableHeaderRow>
    </DataTableHeader>
    <DataTableBody>
      {rows.length === 0 && <DataTableEmpty>No results</DataTableEmpty>}
      {rows.map((row) => (
        <DataTableRow key={row.id} striped>
          <DataTableCell label="Name">{row.name}</DataTableCell>
          <DataTableCell label="Price" align="end">
            {row.price}
          </DataTableCell>
        </DataTableRow>
      ))}
    </DataTableBody>
  </DataTableGrid>
  <DataTableFooter>
    <span>Showing 1-25 of 80</span>
    <DataTablePagination
      page={1}
      pages={[1, 2, 3, 4]}
      hasNextPage
      onPageChange={setPage}
      labels={{ previous: "Previous", next: "Next", page: (page) => `Page ${page}` }}
    />
  </DataTableFooter>
</DataTable>;
```

`DataTableGrid` takes the grid tracks as a string; `buildColumnGridTemplate()` turns column widths
(`xs`–`xl`) into the same `minmax()` tracks the table uses, and `dataTableUtilityTracks()` adds the
fixed leading and trailing tracks for an expander, selection checkbox, or row actions. Utility cells
take `kind="expander" | "selection" | "actions"`; pinned tracks take `pinned="left" | "right"` plus
the column's `pinIndex` and are positioned by the `--lt-pin-offset-*` variables from
`buildPinnedOffsets()`. Every cell renders its `label` as a stacked caption below the `md`
breakpoint, where rows collapse into cards.
